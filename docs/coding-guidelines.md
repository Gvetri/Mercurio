# Coding guidelines

This document is the single home of the repository's coding rules and of what enforces each one. The
documents under [Where the authorities live](#where-the-authorities-live) own the detail; this
document points to them instead of repeating them.

## Comments policy

KDoc is the only allowed comment form in `.kt` sources and `.kts` build scripts; it is allowed and
never required — document a declaration when the documentation earns its place, and let the code and
its tests speak otherwise. KDoc does not attach to a private declaration. Every other hand-maintained
file carries no comments beyond the [exceptions](#exceptions) below. A comment that records a
constraint is encoded first — as a test, a check, or documentation — and then removed.

For now this is the policy; it is revisitable as the codebase evolves.

### Scope

A **hand-maintained file** passes four tests:

1. **Tracked** — it is committed to the repository.
2. **Text** — it is a text file; a binary artifact cannot carry a comment.
3. **Contributor-authored** — contributors edit its content directly: not generated by a tool, not
   vendored from an outside project.
4. **Code-like** — source, build script, configuration, script, or fixture. Prose documents and
   legal texts are a class of their own: everything in them is prose, not code.

The class table assigns the repository's files. A change that introduces a new file class decides it
here, in the same change.

| Class | Files | Decision |
| --- | --- | --- |
| **In scope** | Kotlin sources and build scripts (`.kt`, `.kts`); CI configuration, workflows, and repository scripts (`.github/workflows/*.yml`, `.github/quality-gate/required-checks.txt`, `.github/scripts/**`); the detekt configuration (`config/detekt/detekt.yml`); tooling (`tools/**`); fixtures in comment-capable formats (Maestro flows in `.yaml`, contract fixtures in `.sse`, `fixtures/hermes/pinned-fixture.properties`); Android manifests and resources (`.xml`); root configuration and lists (`.editorconfig`, `.gitignore` files, `gradle.properties`, `gradle/libs.versions.toml`, `feature/entry/presentation/src/test/roborazzi-baselines.txt`) | The comments policy applies |
| **Inert** | Formats that cannot carry comments: strict JSON (the `.json` fixtures), digests (`.github/release-certificate.sha256`), certificate material (`fixtures/hermes/journey-tls/*.pem`, `fixtures/hermes/journey-tls/*.p12`) | Nothing to remove or check |
| **Excluded** | Generated files (the Gradle wrapper — `gradlew`, `gradlew.bat`, `gradle/wrapper/**` — stays exactly as generated); binary artifacts (`.png` baselines, `.jar`); prose documents (`.md`); legal texts (`LICENSE`) | Outside the policy |

### Exceptions

- **Tool directives the tool requires**: a shebang, `# noqa`, `# shellcheck`, a parser directive such
  as the Dockerfile `# syntax=` line. They serve the tool, not the reader.
- **License headers**: where a file needs one.

## Rule ↔ enforcement index

Every rule below names what fails when it is broken — a check, task, or test — and a rule with no
mechanical enforcement is marked as such. `./gradlew qualityGate` runs the gate locally, and
[Quality gates](quality-gates.md) records what each named check executes and the declared scopes and
thresholds.

| Rule | What fails when it is broken |
| --- | --- |
| **Comments policy** ([above](#comments-policy)) | No mechanical check yet — detekt reports only two comment shapes: a comment attached to a private declaration (`CommentOverPrivateFunction`, `CommentOverPrivateProperty`), and a comment containing a forbidden marker (`ForbiddenComment`: `TODO:`, `FIXME:`, `STOPSHIP:`). |
| **Formatting** — Kotlin sources stay formatted | `formatting` check |
| **Static analysis** — the pinned detekt configuration reports no finding and Android lint reports no error | `detekt` check; `static-analysis` check |
| **Architecture boundaries** — feature-first modules with inward dependencies ([architecture](architecture.md)) | `architecture-check` check |
| **Test-first changes** — a behavioral change starts from a focused failing test ([CONTRIBUTING](../CONTRIBUTING.md)) | No mechanical check — code review |
| **Unit tests** — every declared scope runs; no test is skipped | `unit-tests` check |
| **Test doubles** — a deterministic double at every declared datasource and repository boundary; no mocking framework | `architecture-check` check |
| **Coverage and mutation** — declared modules stay at or above the declared thresholds ([quality gates](quality-gates.md)) | `coverage-mutation` check |
| **Compose baselines** — pinned surfaces match their approved Roborazzi baselines | `compose-jvm-tests` check |
| **Commit messages** — a Conventional Commit pull-request title and commits | `commit-message` check |
| **Branches and pull requests** — one issue-scoped branch `<type>/<issue>-<short-description>`, a pull request against protected `main`, a squash merge ([workflow](protected-main-workflow.md)) | The `Main` ruleset refuses a non-conforming merge; the `conformance` check verifies the configuration still implements it |
